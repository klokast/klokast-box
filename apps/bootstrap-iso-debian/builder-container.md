Run these commands from the deployment server:

```sh
cd /home/codex/src/klokast/klokast-box
ansible/bin/bootstrap-live-iso build-builder --resources-registry path/to/platform-resources.yml
ansible/bin/bootstrap-live-iso build-iso
ansible/bin/bootstrap-live-iso transfer-iso
ansible/bin/bootstrap-live-iso stop-builder
ansible/bin/bootstrap-live-iso remove-builder
```

The same sequence is available as one command:

```sh
ansible/bin/bootstrap-live-iso all --resources-registry path/to/platform-resources.yml
```

The registry must enable `bootstrap-iso-debian` with an unexpired privileged
builder approval. See `apps/bootstrap-iso-debian/coding-instructions.md`.

Node name and Tailscale auth key are not build inputs. After the mini PC boots
the ISO, open `http://kk.local/` or `http://klokast.local/` on the DHCP LAN,
enter the node name such as `duh`, and paste a `tskey-auth-*` generated by a
tailnet admin permitted to assign `tag:bootstrap`.
If Tailscale assigns a suffixed bootstrap name, the portal asks only for a new
box name and uses visible Tailscale machine names from `tailscale status --json`
for best-effort client-side validation.

The script builds the ISO inside the `bootstrap-live-builder` Podman container
on `yii-bak`. The container has its own Tailscale identity tagged `tag:back`
and uploads artifacts directly to the NanoKVM over the full MagicDNS name built
from `tailscale status --json`. The Tailscale IP is not hardcoded.
Inside the builder container, public DNS is kept separate from Tailscale DNS so
Debian mirror resolution works; the upload scripts resolve the NanoKVM target
at runtime with `tailscale ip`.

Artifacts are written under:

```text
/srv/bootstrap-live-builder/output/
```

and only the Debian Live ISO plus its SHA512 checksum are transferred to the NanoKVM
Tailscale host:

```text
root@oob.<tailnet>.ts.net:/data/
```

Expected artifact names:

```text
klokast-bootstrap-debian-trixie-amd64.iso
klokast-bootstrap-debian-trixie-amd64.iso.sha512
```
